## Safe Handling Rules

1. **Never manually edit** auto-generated tool directories (`.qoder/`, `.qodo/`, `.trae/`, `.windsurf/`, `.gemini/`) — they are managed by their respective tools.
2. **Project rules** in AI tool directories should reference `AGENTS.md` as the single source of truth — not duplicate rules inline.
3. **If a tool directory causes CI issues**, add it to `.gitignore`.
4. **New AI tools** should add their config directory to `.gitignore` and document it here.
5. **Shared editor settings** (`.vscode/settings.json`, `.vscode/extensions.json`) are safe to commit; personal settings go in `.gitignore`.
6. **`_guidelines/`** must be committed — it is the mirrored source of all engineering standards that AI agents load. Run `sync-guidelines.ps1` whenever the global guidelines repo is updated.

## Special Notes for This Project

### `_guidelines/` — Always Commit
Unlike most generated directories, `_guidelines/` MUST be committed. It is the mirrored copy of the global engineering guidelines that AI agents (Antigravity, Cursor, Gemini, Copilot) read at the start of each session. Without it, AI agents fall back to generic patterns instead of project-specific rules.

To refresh after global guidelines are updated:
```powershell
.\sync-guidelines.ps1
```

### Database Files — Never Commit
The SQLite database (`*.db`, `*.db-shm`, `*.db-wal`) contains real user data (tenant records, payment history, lease contracts). These MUST be in `.gitignore`. The application handles its own backup mechanism (SRS M-13 — Backup & Restore).

### `out/` and `release/` — Never Commit
These are generated by `electron-vite build` and the Electron packager. They can be hundreds of MB. Always in `.gitignore`. Distribute the installer through a dedicated file share or USB — not Git.
